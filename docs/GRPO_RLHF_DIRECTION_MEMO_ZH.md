# GRPO / RLHF 后续方向备忘录

## 1. 当前定位

本备忘录只用于开学会议讨论，不代表已经选定研究方向，也不授权当前阶段开发或训练新算法。

当前优先级是理解第一篇 GPPO 论文和已有 300 轮结果。第二篇 PCRL 只做概念阅读；GRPO/RLHF 的具体修改必须等学长和老师确认研究问题后再开始。

## 2. 四类方法的边界

### GPPO

当前项目中的 GPPO 是图编码器、动态动作掩码、事件触发同步和 PPO 的组合，用于动态 UAV 任务分配。

### GRPO

GRPO 通常对同一 prompt 采样一组回答，通过组内相对奖励估计优势，减少或取消传统 critic 的依赖，并使用 KL 约束控制策略偏移。

### RLHF

RLHF 的典型流程是：

```text
人工比较/偏好数据
→ 奖励模型或直接偏好目标
→ PPO/GRPO 等策略优化
→ 安全性与对齐评估
```

### PCRL / PreCo

第二篇论文输入显式数值 preference vector，在多目标 RL 中学习可控策略。它不是人工偏好建模，也不直接等于 RLHF。

## 3. 第一篇论文对 GRPO/RLHF 的潜在启发

### 方向 A：图结构奖励模型

假设：当任务、约束、步骤依赖或评价标准具有明确结构时，将其建模为图可能比扁平拼接更有效。

可能做法：

- 将推理步骤、工具调用和约束表示为异构节点；
- 使用图编码器输出 reward model 的结构化表示；
- 显式表示前置条件、引用、矛盾和因果关系；
- 将图一致性作为额外奖励或验证信号。

需要验证：

- 图结构是否真实存在，而不是为了使用 GNN 强行构图；
- 相对普通 Transformer reward model 是否有稳定收益；
- 构图成本是否抵消训练收益。

### 方向 B：事件触发式偏好查询

假设：类似“关键事件才通信”，只有在模型不确定或策略变化显著时才请求人工标注，可以降低 RLHF 标注成本。

可能的触发信号：

- reward model ensemble 分歧；
- preference margin 过小；
- policy KL 突变；
- 高风险任务或约束违规；
- 新任务分布或明显 OOD 样本；
- 同组回答奖励近似并列。

需要比较：

- 随机采样；
- 固定频率标注；
- 不确定度采样；
- 事件触发采样。

主要指标：标注数量、最终性能、校准、误触发率、漏触发率和单位标注成本收益。

### 方向 C：图感知 GRPO 分组

假设：GRPO 的 group 构造直接影响相对优势质量。若组内回答难度、结构或策略不可比，相对奖励可能噪声很大。

可能做法：

- 按问题难度或任务图结构分组；
- 保证组内样本共享约束但采用不同推理路径；
- 对重复/同质回答去重；
- 使用图距离或语义距离控制组内多样性；
- 对组内奖励方差过小的样本触发重采样。

需要验证：

- 优势估计方差；
- group reward spread；
- 有效梯度比例；
- 训练稳定性和最终任务性能。

### 方向 D：多目标相对奖励

假设：正确性、安全性、格式、效率等目标可能冲突，过早压缩成一个标量会隐藏冲突。

可能做法：

- 先保留向量奖励，再形成组内相对优势；
- 分析不同目标的梯度冲突；
- 使用显式 preference 控制不同训练/部署需求；
- 借鉴 PreCo、MGDA 或其他多目标梯度方法；
- 将部分指标设为硬约束而不是偏好目标。

主要风险：

- 量纲和归一化决定结论；
- 目标数增加后采样复杂度迅速上升；
- 显式数值偏好不等于真实人类偏好；
- 多目标方法的额外复杂度可能没有实际收益。

### 方向 E：自适应样本/反馈 Gate

假设：第一篇 Adaptive Gate 的思想可以迁移到样本或反馈加权，但原始 Gate 已出现负结果，因此只能作为待验证假设。

可能做法：

- 对不同 judge/reward 信号动态加权；
- 对组内样本按可信度或信息量加权；
- 根据任务类型选择反馈通道；
- 对可能引入噪声的反馈进行抑制。

必须设置 NoGate、固定权重和简单 attention 对照，避免只证明模型更复杂。

## 4. 第二篇论文当前只需要掌握的内容

- MOMDP 使用向量奖励；
- policy 和 critic 以 preference vector 为条件；向量 value 可分别估计各目标的未来回报，再根据偏好进行标量化或多目标更新；
- 线性加权不一定覆盖完整 Pareto front；
- PreCo 将共同改进方向与偏好相似度梯度结合；
- Hypervolume 衡量覆盖，Cosine Similarity 衡量偏好可控性；
- 训练后还可能需要 preference calibration。

概念上可写为 `π(a|s,w)` 与 `V⃗(s,w)`：同一策略接收不同偏好向量 `w` 后，应产生不同的目标权衡。这里的显式数值偏好不同于 RLHF 中从人工比较学习出的 reward model。

当前不运行 Fruit-Tree、MO-Reacher，不接入 GPPO，也不设计七维 Preference-GPPO。

## 5. 开会时建议确认的问题

1. 研究对象是语言模型 GRPO，还是一般强化学习中的相对策略优化？
2. 想改的是数据采样、group 构造、奖励模型、优势估计还是优化目标？
3. 是否有真实偏好数据、judge 模型或人工标注预算？
4. 任务是否具有适合图建模的稳定结构？
5. 多目标是用户可控偏好，还是安全/格式等硬约束？
6. 最终希望降低成本、提升性能、提高稳定性，还是增强可控性？
7. 采用哪些公开任务、基线和评估指标？
8. 计算资源能否支持多种子和消融？
9. 第二篇 PCRL 是需要完整复现，还是只借鉴梯度思想？
10. 第一篇论文的哪一部分最值得迁移：图表示、事件触发、Gate 还是动态掩码？

## 6. 会议后的决策树

```text
老师首先确定核心问题
        │
        ├─ 标注成本高 → 事件触发式偏好查询
        │
        ├─ group 优势噪声大 → 图/难度感知分组
        │
        ├─ reward model 缺少结构 → 图结构奖励模型
        │
        ├─ 多目标冲突 → 向量奖励 + 多目标 GRPO
        │
        └─ 只需标准 GRPO 基线 → 暂不引入 GPPO/PCRL
```

无论选择哪条路线，都应先建立简单、可复现的标准 GRPO 基线，再引入一个明确机制，并保留等参数量或等计算量对照。
